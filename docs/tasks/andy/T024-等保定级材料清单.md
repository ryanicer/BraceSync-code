## 四、已具备的安全措施汇总

| 措施 | 实现方式 | 对应等保要求 |
|------|----------|-------------|
| 身份认证 | JWT Token + RBAC 角色权限控制 | 应用安全-身份鉴别 |
| 传输加密 | HTTPS/TLS 1.2+（T066 部署） | 网络安全-通信完整性 |
| 网络隔离 | Docker 网络隔离（生产/Staging 独立网络） | 网络安全-边界防护 |
| 访问控制 | Nginx 反向代理 + Gateway 路由白名单 | 应用安全-访问控制 |
| 数据备份 | pg_dump 到 COS 三级保留（7日/4周/3月） | 数据安全-数据备份恢复 |
| 恢复演练 | Staging 定期恢复演练（RTO 小于等于 4h） | 数据安全-灾难恢复 |
| 敏感数据加密 | 手机号 AES 加密、设备密钥加密 | 数据安全-数据保密性 |
| 安全审计 | Docker 日志 + Nginx 访问日志 + 应用日志 | 安全审计-日志审计 |
| 容器安全 | Docker 容器隔离、只读挂载、资源限制 | 主机安全-入侵防范 |
| 云安全防护 | 腾讯云安全组、DDoS 防护、监控告警 | 网络安全-入侵防范 |

## 五、待补充项与建议

1. **渗透测试**：建议每半年执行一次第三方渗透测试，覆盖 Web API 和管理后台
2. **代码审计**：建议对核心服务（user-service、gateway）进行安全代码审计
3. **漏洞扫描**：建议部署定期漏洞扫描（可使用腾讯云主机安全）
4. **应急响应预案**：需编制完整的安全事件应急响应预案，明确分级响应流程
5. **数据脱敏**：Staging 环境恢复生产数据后，应对患者敏感信息进行脱敏处理
6. **密钥轮换**：JWT_SECRET、PHONE_ENC_KEY、DEVICE_SECRET_ENC_KEY 应制定定期轮换策略
7. **日志集中化**：建议部署 ELK/Loki 进行日志集中收集和分析
8. **监控告警**：已有 Prometheus + Grafana，需补充安全告警规则
