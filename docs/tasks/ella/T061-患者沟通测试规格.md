```
└─ el-dialog                      (反馈详情 + status=pending 时的回复 textarea + "回复并标记")

Script 关键行为：
  - fetchFeedbacks({ keyword })         → USE_MOCK → mockFeedbacks(params)
  - processFeedbackApi(id, reply?)      → USE_MOCK → delay() return  (⚠️ 不更新 FEEDBACKS 内存)

                                            + ElMessage.success + 关闭 dialog + loadData()
  - markResolved(row)                   → 调用 processFeedbackApi(id) → 手动 row.status = 'resolved'
                                            + row.handler 兜底 + ElMessage.success
```

## 三、前端交互验收标准

### 3.1 打开微信客服后台按钮（核心缺口 · 实现方补）

1. **可见**：`.page-toolbar` 区域内有按钮，文案 = "打开微信客服后台"（可带图标，不影响文案匹配）
2. **跳转正确**：点击后触发 `window.open('https://mpkf.weixin.qq.com/', '_blank')` 或等价新窗口打开机制；新页 URL 必须包含 `mpkf.weixin.qq.com`
3. **注释说明**（设计源有则必加）：按钮旁或 tooltip 标注"小程序客服消息 · 需使用运营账号登录微信公众平台"
4. **权限**：所有能访问 `/communication` 的角色（admin / cs）均可见；doctor 无此页权限不涉及

### 3.2 反馈列表

1. 首屏自动加载列表，表格行 ≥4（mock 有 4 条）
2. 列按顺序渲染：反馈ID / 患者（patientId → 姓名映射） / 类型 / 内容 / 提交时间（`MM-DD HH:mm`） / 状态 tag（pending=warning / replied=primary / resolved=success） / 处理人 / 操作
3. 操作列："详情"按钮全量可见；"标记已处理"仅在 `status !== 'resolved'` 时可见
4. 搜索框输入关键词 → 点"查询"或回车 → 列表按 content / patientId 过滤

### 3.3 详情 / 回复对话框

1. 点任一行"详情" → 弹出 `el-dialog`，标题含 `反馈 FB-XXX`
2. `el-descriptions` 显示字段：患者 / 类型 / 内容 / 提交时间 / 回复（若有 replyContent）
3. 若 `status === 'pending'`：对话框底部显示 `el-input textarea`（占位"回复内容（协调微信客服后填写）"）+ 按钮"回复并标记"
4. 填写回复后点"回复并标记" → 调用 `processFeedbackApi(feedbackId, replyText)` → ElMessage 成功 → 对话框关闭 → 列表 loadData() 刷新

### 3.4 标记已处理（行内按钮）

1. 非 resolved 状态行可见"标记已处理"按钮
2. 点击 → 调用 `processFeedbackApi(feedbackId)`（不传 reply）→ ElMessage "已标记处理" → 行内状态 tag 变为 "已解决"

### 3.5 客服角色权限提示

1. cs 角色账号（"客服小美"）登录进入 `/communication` → 顶部 `el-alert` 可见
2. Alert title 含 "客服角色：仅可查看反馈与标记处理状态" 字样

**Popup 双断言策略**（CI 兼容）：
1. 优先 `page.waitForEvent('popup')`：真实浏览器/网络正常环境能拿到 popup 页 URL
