## 二、端点契约

### 统一约定
- 统一响应体：`{ "code": 0, "message": "success", "data": {...} }`
- 错误码：`CodeInvalidParam=10400(400)` / `CodeNotFound=10404(404)` / `CodeConflict=10409(409)` / `CodeForbidden=10403(403)` / `CodeInternal=90001(500)`
- 鉴权：admin 域，gateway JWT + RBAC（操作人由 gateway 注入 `X-User-Id` 头）
- 时间格式：RFC3339（`2006-01-02T15:04:05Z07:00`）
- 可空字段：指针类型，缺省为 `null`

### 端点 1：创建患者

`POST /api/v1/admin/patients`

**请求体** `CreatePatientRequestDTO`：
```json
{
  "name": "张晓宇",           // 必填，非空（trim 后 ≥1 字符）
  "gender": "male",          // 可选，枚举 {male, female}；缺省 null
  "age": 14,                 // 可选，范围 [0, 150]
  "diagnosis": "胸椎右侧凸", // 可选，自由文本
  "cobbAngle": 28.0,         // 可选，范围 [0, 180]
  "deviceId": null,           // 可选，设备 ID（换绑属后续，创建时可不绑）
  "teamId": "TEAM01",        // 可选，团队 ID；存在性校验
  "doctorId": "D0001"        // 可选，主治医生 ID
}
```

**响应** `data: AdminPatientDTO`（HTTP 200）：
```json
{
  "patientId": "P20260007",   // 系统生成（P + 年份 + 6 位序号，实现方定生成规则）
  "name": "张晓宇",
  "gender": "male",
  "age": 14,
  "diagnosis": "胸椎右侧凸",
  "cobbAngle": 28.0,
  "deviceId": null,
  "teamId": "TEAM01",
  "doctorId": "D0001",
  "status": "active",         // 新建默认 active
  "createdAt": "2026-08-27T10:00:00+08:00",
  "updatedAt": "2026-08-27T10:00:00+08:00",
  "teamName": "脊柱矫形一组",
  "doctorName": "李医师"
}
```

**校验规则**：
| 条件 | HTTP | code | 说明 |
|---|---|---|---|
| name 空 / 纯空白 | 400 | 10400 | name is required |
| gender 非枚举值 | 400 | 10400 | invalid gender: male\|female |
| age 越界（<0 或 >150） | 400 | 10400 | invalid age range |
| cobbAngle 越界（<0 或 >180） | 400 | 10400 | invalid cobbAngle range |
| teamId 不存在 | 400 | 10400 | team not found |
| **重复创建**（name+age+diagnosis 完全相同） | 409 | 10409 | patient already exists |
| 非法 JSON body | 400 | 10400 | invalid request body |
| store 错误 | 500 | 90001 | create patient failed |

**幂等决策（待 Boss 评审）**：设计"添加患者"表单无手机号字段，无天然唯一键。本规格采用 `name + age + diagnosis` 三元组完全相同判重 → 409。若 Boss 认为需更严格（如要求手机号），实现方调整。

### 端点 2：分配团队

`PUT /api/v1/admin/patients/:patientId/team`

**请求体** `AssignTeamRequestDTO`：
```json
{ "teamId": "TEAM02" }   // 必填，非空
```

**响应** `data: AdminPatientDTO`（HTTP 200）：更新后的患者（teamId/teamName 变更）。

**校验规则**：
| 条件 | HTTP | code | 说明 |
|---|---|---|---|
| teamId 空 | 400 | 10400 | teamId is required |
| teamId 不存在 | 400 | 10400 | team not found |
| patientId 不存在 | 404 | 10404 | patient not found |
| 非法 JSON body | 400 | 10400 | invalid request body |
| store 错误 | 500 | 90001 | assign team failed |

**幂等**：分配到患者当前已绑定的同一 teamId → 200 no-op，返回当前患者（不变更 updatedAt）。

### 端点 3：批量绑定

`POST /api/v1/admin/patients/batch-bind`

**请求体** `BatchBindRequestDTO`：
```json
{
  "patientIds": ["P20260001", "P20260002", "P2026XXXX"],  // 必填，非空数组
  "teamId": "TEAM01"                                       // 必填，非空
}
```

**响应** `data: BatchBindResultDTO`（HTTP 200，部分失败仍 200）：
```json
{
  "successCount": 2,
  "failedCount": 1,
  "failures": [
    { "patientId": "P2026XXXX", "reason": "patient not found" }
  ]
}
```

**校验规则**：
| 条件 | HTTP | code | 说明 |
|---|---|---|---|
| patientIds 空 / 缺失 | 400 | 10400 | patientIds must not be empty |
| teamId 空 | 400 | 10400 | teamId is required |
| teamId 不存在 | 400 | 10400 | team not found |
| 非法 JSON body | 400 | 10400 | invalid request body |
| store 错误 | 500 | 90001 | batch bind failed |

**部分失败策略**：不整体回滚。存在患者成功分配，不存在患者计入 `failures`（reason="patient not found"）。HTTP 仍 200。

## 三、前端交互验收标准

### 添加患者（顶栏「+ 添加患者」按钮）
1. 点击「+ 添加患者」→ 弹窗可见，表单含字段：姓名（必填）/ 性别（下拉 male/female）/ 年龄 / 诊断 / Cobb角 / 团队（下拉）/ 主治医生（下拉）
2. 姓名为空时确认按钮禁用或提交后表单校验提示
3. 合法提交 → ElMessage 成功提示 + 弹窗关闭 + 列表新增一行（首条）
4. 重复创建（同姓名+年龄+诊断）→ ElMessage 错误提示"患者已存在"

### 管理团队（每行「管理团队/分配团队」按钮 → 弹窗 WB-08）
1. 已分配团队患者行显示「管理团队」按钮；未分配（status=pending）显示「分配团队」按钮
2. 点击按钮 → 弹窗 WB-08 可见，显示：患者信息（只读）+ 当前绑定团队（只读）+ 更改为（团队下拉）
3. 选择新团队 → 确认绑定 → ElMessage 成功 + 弹窗关闭 + 行团队列更新
4. 分配到当前已绑定团队 → 幂等成功（无错误）

### 批量绑定（独立 card WB-09）
1. 页面下方「批量患者-团队绑定」card 可见
2. 勾选多名未分配患者 → 选择团队 → 确认分配
3. 成功 → ElMessage 成功提示 + 患者团队列更新
4. 部分失败 → ElMessage 警告提示成功数与失败数
