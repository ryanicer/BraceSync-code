## 3. 问题详情列表（按严重等级降序）

### ❌ 高优先级（功能不通 / 契约阻断）

#### Q1：实时快照 realtime 端点字段契约不匹配 + 压力热力图 20 点位缺失
- **页面**：实时监控 `/monitor` + 压力热图
- **操作步骤**：登录 ops_admin 后请求 `GET /api/v1/patients/P20260001/realtime`（5 个患者全测）
- **预期**（对照 `apps/admin-web/src/api/index.ts:94-98` + mock/patients RealtimeSnapshot 类型）：响应 JSON 含 `status` / `todayHours` / **`pressureMax`**（数值，如 185）/ `maxPoint`（如 "P05"）/ **`pressureHeatmap`**（长度=20 的 int/float 数组，对应 4×5 网格色阶渲染）/ `events` / `alerts`
- **实际**：字段集合 = `[status, todayHours, maxPressure, maxPoint, events, pressureRecords, alerts]`；① `pressureMax` → 实际是 `maxPressure`（字段名错位）；② **`pressureHeatmap` 完全不存在**，后端给出 `pressureRecords = []`（长度 0 空数组）；③ 5 人 maxPressure=0、todayHours=0、pressureRecords=空；④ maxPoint 空字符串
- **严重等级**：❌ **高（功能阻断）**。前端实时监控页依赖 `pressureHeatmap[20]` 直接渲染 `PressureHeatmap.vue` 4×5 网格，undefined/len=0 → 热力图全灰；`pressureMax` 字段名不匹配 → 压力最大点显示 NaN 或空白
- **归属类别**：**后端端点（data-service realtime handler 契约修正）** + 前端字段同步（若后端保留 pressureRecords 命名，则前端 api/index.ts + RealtimeSnapshot 类型同步改名，但 heatmap 必须产出 ≥20 点数据）
- **复现命令**：
  ```powershell
  $body = @{username="ops_admin";password="admin123"} | ConvertTo-Json
  $login = Invoke-RestMethod -Uri "http://127.0.0.1:2080/api/v1/auth/login" -Method POST -Body $body -ContentType "application/json"
  $h = @{Authorization="Bearer $($login.data.token)"}
  # 检查字段差异
  $r = Invoke-RestMethod -Uri "http://127.0.0.1:2080/api/v1/patients/P20260001/realtime" -Headers $h
  $r.data | ConvertTo-Json -Depth 5  # 对比期望 pressureMax vs 实际 maxPressure；pressureRecords vs pressureHeatmap
  ```

#### Q5：矫形计划写操作 403（身份限定）+ 医生管理独立页路由缺失（架构差异）
- **页面**：矫形日志 `/orthosis-log` "新建矫形计划"按钮 + 侧边栏菜单入口
- **子项 Q5-a：新建矫形计划 ops_admin 身份 403**
  - **操作**：请求 `POST /api/v1/patients/P20260003/orthosis-plans` body: `{"content":"验收测试计划 v1"}` （Authorization=Bearer ops_admin token）
  - **预期**：HTTP 200 code=0，返回 `{planId, version, createdAt}`
  - **实际**：HTTP **403 Forbidden**（空 body）；后端 `handler.go` savePlan 显式调用 `DoctorIDByAdmin(X-User-Id)`，未命中 doctors 表则返回 `ErrForbidden("doctor identity required to save orthosis plan")`
  - **严重等级**：❌ 高（功能不通，但属**正确的权限边界**，非代码 bug）
  - **归属类别**：**权限/角色设计**（运营管理员 vs 医生分工；若验收需闭环，改用 ROLE_DOCTOR 绑定账号如 D0001 李医师登录后重试即可）
- **子项 Q5-b：医生管理独立路由页缺失**
  - **操作**：对比 `apps/admin-web/src/router/index.ts` 12 条业务路由 vs 任务文档 14 项清单第 8 项"医生管理"独立页
  - **预期**：12 条业务路由 + 1 条 /doctors 路由共 13 项
  - **实际**：路由仅 12 条，无独立 `/doctors` 页面入口；医生数据仅通过：① /api/v1/doctors API ② Dashboard 医生排行表 ③ 患者详情抽屉"主治医生"名映射 三处呈现
  - **严重等级**：⚠️ 中（架构差异，非 bug，属于"入口合并"设计决策但与验收清单第 8 项单列不一致）
  - **归属类别**：**架构差异/前端路由**（PM 决策：补独立路由 or 保留当前合并入口）
- **复现命令（Q5-a）**：
