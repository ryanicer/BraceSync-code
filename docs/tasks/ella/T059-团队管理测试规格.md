## 一、范围

对齐设计源 `团队管理.html` 的写功能（WB-22 团队 CRUD + WB-23~27 成员管理），定义 6 个新后端端点契约 + 前端交互验收标准。

| # | 设计功能 | 后端新端点 | 前端需补 |
|---|---|---|---|
| 1 | + 新建团队（名称/负责人/描述） | `POST /api/v1/teams` | 新建团队弹窗 |
| 2 | 编辑团队（行内编辑） | `PUT /api/v1/teams/:teamId` | 编辑弹窗（预填） |
| 3 | 删除团队（行内删除） | `DELETE /api/v1/teams/:teamId` | 删除确认 |
| 4 | + 添加成员（选择成员 + 分配角色） | `POST /api/v1/teams/:teamId/members` | 成员管理抽屉 + 添加成员弹窗 |
| 5 | 编辑成员（角色/职称） | `PUT /api/v1/teams/:teamId/members/:memberId` | 成员编辑弹窗 |
| 6 | 移除成员（幂等） | `DELETE /api/v1/teams/:teamId/members/:memberId` | 成员移除按钮 |

**范围排除**（设计有但本阶段不做，标注供 Boss 评审）：
- 团队列表 8 列扩展（负责人/创建时间/状态/操作列）：属读路径补齐，实现方在 GET /teams 扩展 TeamRow/TeamDTO 即可，本规格不新增端点（仅在契约中标注期望列）
- 成员搜索 + 角色筛选：前端交互层，不涉及新端点
- 统计 card（团队总数/成员总数/管理患者/待分配患者）：前端聚合，复用既有 GET

> ⚠️ **成员模型说明**（待 Boss 评审）：现有 `GET /teams/:teamId/members` 返回 `{doctors, technicians}`（医生+技师两类，按 team_id 归属）。本规格的成员写操作沿用此模型——**成员 = 归属本团队的医生或技师**，用 `memberType`（`doctor`|`technician`）+ `memberId` 定位。设计源成员表角色为 主任医师/主治医师/康复师/护士，假设护士/康复师归入 `doctors` 表（以 `title` 区分）；若实际为独立表，实现方新增 `memberType` 取值并同步本规格。**此为契约假设，标"待 Boss 评审"**。

## 二、端点契约

### 统一约定
- 统一响应体：`{ "code": 0, "message": "success", "data": {...} }`
- 错误码：`CodeInvalidParam=10400(400)` / `CodeNotFound=10404(404)` / `CodeConflict=10409(409)` / `CodeForbidden=10403(403)` / `CodeInternal=90001(500)`
- 鉴权：admin 域，gateway JWT + RBAC（操作人由 gateway 注入 `X-User-Id` 头）
- 时间格式：RFC3339（`2006-01-02T15:04:05Z07:00`）
- 可空字段：指针类型，缺省为 `null`
- teamId 生成规则：`TEAM` + 年份后两位 + 4 位序号（如 `TEAM26001`），具体由实现方定，本规格仅断言非空且以 `TEAM` 开头

### 端点 1：创建团队

`POST /api/v1/teams`

**请求体** `CreateTeamRequestDTO`：
```json
{
  "name": "骨科一组",      // 必填，非空（trim 后 ≥1 字符，≤50）
  "leader": "D0001",      // 必填，负责人 doctorId，存在性校验
  "description": "骨科诊疗组"  // 可选，自由文本，≤200
}
```

**响应** `data: TeamDetailDTO`（HTTP 200）：
```json
{
  "teamId": "TEAM26001",
  "name": "骨科一组",
  "leader": "D0001",
  "leaderName": "张主任",
  "memberCount": 0,
  "patientCount": 0,
  "description": "骨科诊疗组",
  "status": "active",
  "createdAt": "2026-08-29T10:00:00+08:00"
}
```

**校验规则**：
| 条件 | HTTP | code | 说明 |
|---|---|---|---|
| name 空 / 纯空白 | 400 | 10400 | name is required |
| name 超 50 字符 | 400 | 10400 | name exceeds 50 chars |
| leader 空 | 400 | 10400 | leader is required |
| leader 不存在（doctorId 查无） | 400 | 10400 | leader not found |
| description 超 200 字符 | 400 | 10400 | description exceeds 200 chars |
| **name 已存在**（团队名查重命中） | 409 | 10409 | team name already exists |
| 非法 JSON body | 400 | 10400 | invalid request body |
| store 错误 | 500 | 90001 | create team failed |

**name 唯一键**：团队名（trim 后）唯一。store.CreateTeam 内部按 name 查重，命中返回 `ErrTeamNameExists` → handler 映射 409。

### 端点 2：编辑团队

`PUT /api/v1/teams/:teamId`

**请求体** `UpdateTeamRequestDTO`：
```json
{
  "name": "骨科一组（更名）",  // 必填，非空
  "leader": "D0002",        // 必填，doctorId 存在性校验
  "description": "更新描述"     // 可选
}
```

**响应** `data: TeamDetailDTO`（HTTP 200）：更新后的团队。

**校验规则**：
| 条件 | HTTP | code | 说明 |
|---|---|---|---|
| teamId 不存在 | 404 | 10404 | team not found |
| name 空 | 400 | 10400 | name is required |
| leader 不存在 | 400 | 10400 | leader not found |
| **name 已被其他团队占用**（查重排除自身） | 409 | 10409 | team name already exists |
| 非法 JSON body | 400 | 10400 | invalid request body |
| store 错误 | 500 | 90001 | update team failed |

**幂等**：提交与当前完全相同的 name/leader/description → 200 no-op（返回当前团队，不变更 updatedAt）。

### 端点 3：删除团队

`DELETE /api/v1/teams/:teamId`

**响应** `data: null`（HTTP 200）。

**校验规则**：
| 条件 | HTTP | code | 说明 |
|---|---|---|---|
| teamId 不存在 | 404 | 10404 | team not found |
| **团队被引用**（patients.team_id 或 doctors/technicians.team_id 命中） | 409 | 10409 | team in use: {N} patients, {M} members |
| store 错误 | 500 | 90001 | delete team failed |

#### 删除约束策略（⚠️ 待 Boss 评审决策）

团队被患者/成员引用时的处理，Ella 建议 **方案 A：拒绝删除（reject-if-referenced）**：

| 方案 | 行为 | 优点 | 缺点 | Ella 评估 |
|---|---|---|---|---|
| **A. 拒绝删除**（推荐） | 被引用 → 409，提示引用计数；管理员须先重分配患者/移除成员再删 | 数据安全、显式、审计可追 | 删除前需手动清理 | ✅ 推荐：医疗域强引用，误删致患者孤儿记录风险高 |
| B. 级联置空 | 引用方 team_id 置 NULL 后删团队 | 一键完成 | 患者瞬间无团队、历史归属丢失 | ❌ 不建议：医疗数据不应静默解绑 |
| C. 软删除（status=deleted） | 标记删除保留行，引用不变 | 保历史、可恢复 | 查询须全局过滤 status，列表/绑定语义复杂 | ⚠️ 备选：若需保留团队历史可考虑，但增加查询复杂度 |

**Ella 建议 A**：删除前 store.DeleteTeam 统计引用计数（patients + members），命中返回 `ErrTeamInUse`（携带计数）→ handler 映射 409 + 文案含计数。**最终策略以 Boss 评审为准**；本规格 KNOWN_RED 测试按 A 编写（断言 409），若 Boss 选 C 则实现方调整 store 行为 + 测试断言（移除 409 用例改 200）。

### 端点 4：添加成员

`POST /api/v1/teams/:teamId/members`

**请求体** `AddMemberRequestDTO`：
```json
{
  "memberType": "doctor",   // 必填，枚举 {doctor, technician}
  "memberId": "D0002",      // 必填，doctorId / techId
  "role": "主治医师"          // 可选，角色/职称（doctor.title）
}
```

**响应** `data: TeamMemberDTO`（HTTP 200）：
```json
{
  "memberId": "D0002",
  "memberType": "doctor",
  "name": "李医生",
  "role": "主治医师",
  "title": "骨科",
  "phoneMasked": "138****0002",
  "patientCount": 32,
  "joinTime": "2026-08-29T10:00:00+08:00",
  "status": "enabled"
}
```

**校验规则**：
| 条件 | HTTP | code | 说明 |
|---|---|---|---|
| teamId 不存在 | 404 | 10404 | team not found |
| memberType 非枚举值 | 400 | 10400 | invalid memberType: doctor|technician |
| memberId 空 | 400 | 10400 | memberId is required |
| member 不存在（doctor/tech 查无） | 404 | 10404 | member not found |
| **member 已属本团队**（team_id 已等于本 team） | 409 | 10409 | member already in team |
| 非法 JSON body | 400 | 10400 | invalid request body |
| store 错误 | 500 | 90001 | add member failed |

**语义**：store.AddTeamMember 将 doctor/technician 的 team_id 置为本 teamId；role 可选，传则更新 doctor.title（technician 无 title 字段则忽略 role）。

### 端点 5：编辑成员

`PUT /api/v1/teams/:teamId/members/:memberId`

**请求体** `UpdateMemberRequestDTO`：
```json
{
  "memberType": "doctor",   // 必填，定位医生/技师表
  "role": "主任医师"          // 可选，更新角色/职称
}
```

**响应** `data: TeamMemberDTO`（HTTP 200）：更新后的成员。

**校验规则**：
| 条件 | HTTP | code | 说明 |
|---|---|---|---|
| teamId 不存在 | 404 | 10404 | team not found |
| memberType 非枚举值 | 400 | 10400 | invalid memberType: doctor|technician |
| member 不存在或不属本团队 | 404 | 10404 | member not found |
| 非法 JSON body | 400 | 10400 | invalid request body |
| store 错误 | 500 | 90001 | update member failed |

**幂等**：提交与当前相同 role → 200 no-op。

### 端点 6：移除成员

`DELETE /api/v1/teams/:teamId/members/:memberId?memberType=doctor`

**查询参数**：`memberType`（必填，`doctor`|`technician`，DELETE 无 body 故走 query 定位表）。

**响应** `data: null`（HTTP 200）。

**校验规则**：
| 条件 | HTTP | code | 说明 |
|---|---|---|---|
| teamId 不存在 | 404 | 10404 | team not found |
| memberType 非枚举值 | 400 | 10400 | invalid memberType: doctor|technician |
| memberType 缺失 | 400 | 10400 | memberType is required |
| store 错误 | 500 | 90001 | remove member failed |

**幂等**：移除不属本团队的成员（或已移除）→ 200 no-op（不返回 404，符合"移除幂等"语义）。store.RemoveTeamMember 将 doctor/technician 的 team_id 置 NULL，已为 NULL 则 no-op。

> **memberType 传递方式**（待 Boss 评审）：POST/PUT 走 body，DELETE 走 query（DELETE 无 body 约定）。实现方若统一改为 path（`/members/:memberType/:memberId`）或 body，需同步本规格 + 测试。

## 三、前端交互验收标准

### 团队列表（GET /teams 读路径扩展，实现方补列）
1. 顶栏「+ 新建团队」按钮可见
2. 表格 8 列：团队编号 / 团队名称 / 负责人 / 成员数 / 管理患者数 / 创建时间 / 状态 / 操作（成员/编辑/删除）

### 新建团队（顶栏「+ 新建团队」→ 弹窗）
1. 点击 → 弹窗可见，表单字段：团队名称（必填）/ 负责人（下拉，doctor 列表）/ 描述（可选）
2. 团队名称为空时确认按钮禁用或提交后表单校验提示
3. 合法提交 → ElMessage 成功 + 弹窗关闭 + 列表新增一行（首条）
4. 重复名称 → ElMessage 错误提示"团队名称已存在"

### 编辑团队（行内「编辑」→ 弹窗预填）
1. 点击编辑 → 弹窗预填当前团队 name/leader/description，标题"编辑团队"
2. 改名/换负责人提交 → ElMessage 成功 + 弹窗关闭 + 行刷新

### 删除团队（行内「删除」→ 确认）
1. 点击删除 → 确认弹窗（ElMessageBox）"确定删除该团队？"
2. 确认删除 → 成功提示 + 行消失
3. **团队被引用时** → 错误提示含引用计数（"团队被引用：N 患者，M 成员"），不删除

### 成员管理（行内「成员」→ 抽屉/卡片）
1. 点击成员 → 成员管理视图可见，标题"团队: {name} - 成员管理"，含返回按钮
2. 成员表 8 列：姓名 / 角色 / 职称 / 手机号（脱敏）/ 负责患者数 / 加入时间 / 状态 / 操作（编辑/移除）
3. 「+ 添加成员」按钮 → 弹窗：选择成员（下拉搜索 doctor/tech）/ 分配角色（下拉）
4. 添加成功 → ElMessage 成功 + 成员表新增一行
5. 成员已在本团队 → 错误提示"成员已在本团队"
6. 行内「移除」→ 确认后成功提示 + 行消失（幂等：重复移除不报错）

## 五、gateway 路由同步（⚠️ T057 教训）

`services/gateway/cmd/server/proxy_admin.go` 的 `userServiceRoutes` 当前仅注册团队**读**路由：
```
{Get,  "/teams"}
{Get,  "/teams/:teamId/members"}
```

实现方转绿时**必须同步追加 6 条写路由**（否则 gateway 404，前端写操作不通）：
```
{Post,   "/teams"}
{Put,    "/teams/:teamId"}
{Delete, "/teams/:teamId"}
{Post,   "/teams/:teamId/members"}
{Put,    "/teams/:teamId/members/:memberId"}
{Delete, "/teams/:teamId/members/:memberId"}
```

> 本规格 E2E 与后端测试均走 user-service Router（不经 gateway），故 gateway 路由缺口不影响 KNOWN_RED 红态；但实现方转绿集成阶段须补齐，CI 集成测试可加 gateway 代理断言（本阶段未加，标注供实现方）。
