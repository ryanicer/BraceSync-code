## 一、范围

为患者端登录绑定 + WiFi 配网两个状态机搭建 vitest 测试基座并预置 KNOWN_RED 单测。
本阶段仅写测试与测试支撑骨架，不含任何业务实现（页面 / store / 网络 / BLE）。

| 模块 | Stub 路径 | 测试路径 | 覆盖分支数 |
|---|---|---|---|
| 登录绑定状态机 | `src/utils/auth-state.ts` | `tests/unit/auth-state.spec.ts` | 7 |
| WiFi 配网状态机 | `src/utils/wifi-state.ts` | `tests/unit/wifi-state.spec.ts` | 扫描过滤 3 + 进度 4 + 状态码 9 + 超时 5 = 21 |

## 二、登录绑定状态机（PRD §7A.1.1）

### 2.1 wx-login

| code | 状态 | 去向页面 | 验收断言 |
|---|---|---|---|
| `0` | SUCCESS | `/pages/monitor/index` | `state==='SUCCESS'` 且 `targetPage==='/pages/monitor/index'` |
| `10601` | NEED_BIND | `/pages/login/bind` | `state==='NEED_BIND'` 且 `targetPage==='/pages/login/bind'` |
| `10001` | FAIL（凭证错误） | 不跳转（`''`） | `state==='FAIL'` 且 `targetPage===''` 且 `message` 非空 |
| `401` | FAIL（凭证错误） | 不跳转（`''`） | `state==='FAIL'` 且 `targetPage===''` |
| `10502` | ERROR（服务异常） | 不跳转（`''`） | `state==='ERROR'` 且 `targetPage===''` 且 `message` 非空 |
| `502` | ERROR（服务异常） | 不跳转（`''`） | `state==='ERROR'` 且 `targetPage===''` |

**附加断言**：`FAIL(10001).state !== ERROR(10502).state`（凭证错误与服务异常必须区分）。

## 三、WiFi 配网状态机（PRD §7A.9）

### 3.1 扫描过滤

| 输入设备 | 是否保留 | 验收断言 |
|---|---|---|
| `{ name: 'BSYNC-001', is24G: true }` | 保留 | 在结果中 |
| `{ name: 'BSYNC-002', is24G: false }` | 过滤（非 2.4G） | 不在结果中 |
| `{ name: 'OtherDevice', is24G: true }` | 过滤（非 BSYNC- 前缀） | 不在结果中 |
| `{ name: 'BSYNC-003', is24G: true }` | 保留 | 在结果中 |

边界：空输入返回 `[]`；全部不符合返回 `[]`。

### 3.2 进度推进

| 当前 step | 下一步 | 验收断言 |
|---|---|---|
| `0` | `1` | `nextProvisionStep(0) === 1` |
| `1` | `2` | `nextProvisionStep(1) === 2` |
| `2` | `3` | `nextProvisionStep(2) === 3` |
| `3` | `3`（终点不推进） | `nextProvisionStep(3) === 3` |

### 3.3 状态码解析

| code | 解析结果 | 验收断言 |
|---|---|---|
| `0` | progress step 0 | `kind==='progress'` 且 `step===0` |
| `1` | progress step 1 | `kind==='progress'` 且 `step===1` |
| `2` | progress step 2 | `kind==='progress'` 且 `step===2` |
| `3` | progress step 3 | `kind==='progress'` 且 `step===3` |
| `9` | success | `kind==='success'` |
| `-1` | failure 密码错误 | `kind==='failure'` 且 `code===-1` 且 `message` 含「密码」 |
| `-2` | failure 无网络 | `kind==='failure'` 且 `code===-2` 且 `message` 含「网络」 |
| `-3` | failure 地址失败 | `kind==='failure'` 且 `code===-3` |
| `-4` | failure 服务器不可达 | `kind==='failure'` 且 `code===-4` |

### 3.4 超时（15s）

| 耗时 (ms) | 是否超时 | 验收断言 |
|---|---|---|
| `14999` | 否 | `isProvisionTimeout(14999) === false` |
| `15000` | 否（边界） | `isProvisionTimeout(15000) === false` |
| `15001` | 是 | `isProvisionTimeout(15001) === true` |
| `30000` | 是 | `isProvisionTimeout(30000) === true` |

常量断言：`PROVISION_TIMEOUT_MS === 15000`。

## 四、预期红态说明

- **红态方式**：stub 函数返回固定错误占位值（如 `resolveWxLoginResult` 恒返回 `ERROR`，`resolveProvisionStatus` 恒返回 `failure(-1)`，`isProvisionTimeout` 恒返回 `false`）。
- **红态表现**：`npm test` 执行 2 个 spec 文件，断言因 stub 返回值与预期不符而 FAIL（非编译/导入错误）。
- **转绿方式**：Iris Stage 3b 替换 stub 函数体为真实状态映射逻辑，import 路径不变。

## 五、CI 集成

- root `package.json` 的 `test` = `npm run test --workspaces`，patient-miniapp 接入 `vitest run` 后自动被 root `npm test` 覆盖。
- `.github/workflows/ci-fe.yml` 无需修改。
- ⚠️ CI 命令 `npm run test -- --coverage --run` 携带 `--coverage`，但仓库无 `@vitest/coverage-*` 依赖（tech-miniapp 同样无）。本阶段严格镜像 tech-miniapp，不额外引入 coverage 依赖；若 CI 因 coverage 报错，属既有问题，上报 PM/Andy 统一处理。
